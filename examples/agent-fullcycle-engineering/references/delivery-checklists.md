# Agent 交付清单

## 1. 需求清单

- 目标用户是谁。
- 用户想完成什么任务。
- Agent 可以做什么，不可以做什么。
- 成功标准是什么。
- 错误代价是什么。
- 是否需要人工确认。
- 输入数据来自哪里。
- 输出会被谁使用。
- 隐私、合规、权限要求是什么。
- 成本和延迟预算是多少。

## 2. 设计评审清单

- 是否选择了最简单可行架构。
- 是否定义输入和输出 schema。
- 是否定义工具 schema、权限和错误返回。
- 是否有状态模型。
- 是否有停止条件和最大步骤数。
- 是否有澄清、拒绝和人工接管路径。
- 是否有测试计划和 eval 数据集。
- 是否有日志、指标和回滚方案。

## 3. 实现清单

- Prompt 文件可版本化。
- 工具参数经过校验。
- 外部调用有超时和重试。
- 副作用操作有确认或幂等控制。
- RAG 有权限过滤和来源引用。
- 结构化输出有 schema 校验。
- 错误对用户可理解，对工程师可追踪。
- 密钥不写入代码或日志。
- CrewAI 项目中 agent、task、context、Flow state 引用一致。
- 每个副作用工具有 dry-run、确认、幂等或回滚策略之一。

## 4. 测试清单

- 单元测试覆盖核心纯函数。
- 工具 mock 覆盖成功和失败。
- 集成测试覆盖完整 loop。
- Eval 集覆盖常见、边界和高风险场景。
- 安全测试覆盖 prompt injection 和越权。
- 变更后有回归对比。

## 5. 上线清单

- 灰度范围明确。
- 监控指标明确。
- 告警阈值明确。
- 人工接管流程明确。
- 回滚步骤明确。
- 用户反馈入口明确。
- 成本上限明确。
- Smoke test 输入和预期 trace 明确。
- 生产环境变量和密钥来源明确。
- 依赖版本可复现。

## 6. Review 清单

- 是否存在高置信 bug。
- 是否存在安全和权限问题。
- 是否存在性能或成本风险。
- 是否违反项目约定。
- 是否缺少必要测试。
- 是否缺少日志、trace 或错误上下文。
- 是否有硬编码 secret、token、password、api_key。

## 7. Git/PR 清单

- 一个提交只覆盖一个逻辑主题。
- commit message 使用 `feat`、`fix`、`test`、`docs`、`refactor`、`chore`、`ci` 等类型。
- PR 描述包含 summary、changes、tests、risk、deployment、rollback。
- 不提交 `.env`、本地缓存、构建产物或大日志。
- 变更能追溯到 feature brief、plan、task id 或 issue。

## 8. 复盘清单

- 失败案例是否进入 eval 集。
- 是否能从 trace 定位原因。
- 是 prompt、工具、检索、权限、产品边界还是用户体验问题。
- 修复是否只改必要层。
- 是否需要更新文档、runbook 或测试。
