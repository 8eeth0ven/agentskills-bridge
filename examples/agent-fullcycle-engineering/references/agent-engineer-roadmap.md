# Agent 工程师能力路线

## 1. 先理解 Agent 是什么

Agent 可以理解为“会做事的 AI 程序”。普通聊天机器人主要回答问题；Agent 还会根据目标选择下一步、调用工具、读取结果、更新状态，并继续推进任务。

一个最小 Agent 通常包含：

- Model：负责理解、推理、生成。
- Instructions：告诉模型角色、边界、输出格式。
- Tools：让模型查询数据库、调用 API、读写文件、发消息或执行代码。
- State：保存任务进度、上下文、已完成步骤和中间结果。
- Control loop：决定何时继续、何时停止、何时问人。
- Evaluation：判断做得好不好，并防止改坏。

## 2. 小白需要先会什么

先掌握这些基础，不要一开始就追多 Agent 或复杂框架：

- 基础编程：Python 或 TypeScript，能写 API 调用、读写 JSON、处理错误。
- HTTP/API：知道请求、响应、鉴权、状态码、超时、重试。
- Prompt 基础：会写清楚目标、约束、输入变量、输出格式。
- 数据基础：会处理文本、表格、日志，理解结构化和非结构化数据。
- Git 和测试：会提交代码，能写单元测试和简单集成测试。
- 安全意识：知道不要把密钥、隐私、危险操作直接交给模型。

## 3. Agent 工程师要覆盖的能力面

- 产品和需求：定义用户、场景、成功标准、边界、成本和风险。
- 上下文工程：决定给模型什么信息、以什么结构给、什么时候检索。
- 工具设计：设计清晰的函数/API schema、权限、错误返回和幂等行为。
- RAG 和知识库：切分文档、生成向量、检索、重排、引用来源、评估召回。
- 工作流编排：把确定步骤交给代码，把模糊判断交给模型。
- 状态和记忆：区分短期任务状态、长期用户偏好、审计日志和缓存。
- 测试和评估：用固定案例、模拟工具、回归集、安全探针衡量质量。
- 安全和合规：权限控制、数据脱敏、越权防护、提示注入防护、人工审批。
- 部署和运维：日志、追踪、指标、告警、成本、限流、回滚。
- 人机协同：设计澄清问题、确认步骤、人工接管和可解释输出。
- 框架落地：能读懂并调试 CrewAI、LangGraph、OpenAI Agents SDK 或项目自研 agent loop。

## 4. 从浅到深的学习阶段

### 阶段 1：会用模型做稳定输出

目标：能让模型按格式回答，不胡乱输出。

练习：

- 写一个把用户需求整理成 JSON 的小程序。
- 给输出加 schema 校验。
- 保存 prompt 版本和测试样例。

### 阶段 2：会做工具调用 Agent

目标：让模型决定是否调用工具，并处理工具结果。

练习：

- 做一个能查天气、查文件或查数据库的 Agent。
- 给工具加参数校验、超时、错误处理。
- 记录每次工具调用的输入和输出状态。

### 阶段 3：会做 RAG

目标：让 Agent 基于私有知识回答，并能给出处。

练习：

- 对文档做 chunking。
- 生成 embedding 并检索。
- 比较不同 chunk 大小和 top_k 的效果。
- 做一个包含“应该答对”和“不知道就承认”的评估集。

### 阶段 4：会做工作流

目标：把 Agent 从“聊天”变成“可重复业务流程”。

练习：

- 把任务拆成固定步骤。
- 用代码控制流程，用模型处理判断或生成。
- 加入失败重试、人工确认和中断恢复。

### 阶段 5：会测试和上线

目标：修改 Agent 后知道有没有变好或变坏。

练习：

- 建 30 到 100 条代表性 eval case。
- 写 mock tool 测试，避免测试依赖外部系统。
- 加入线上日志、质量反馈和成本监控。

### 阶段 6：会做生产级治理

目标：Agent 出问题能定位、能止损、能持续改进。

练习：

- 设计权限边界和审批策略。
- 做 prompt injection 测试。
- 建立告警、回滚、人工接管和复盘流程。

### 阶段 7：会做框架化和多 Agent 项目

目标：能把复杂 Agent 项目拆成角色、任务、Flow、测试和部署流程。

练习：

- 用 CrewAI 或类似框架定义 `agents.yaml` 和 `tasks.yaml`。
- 做一个带 `@start`、`@listen`、`@router` 的 Flow。
- 给每个 agent 和 task 加验收标准、guardrail 和 trace。
- 模拟一个失败任务，用 replay 或最小复现修复。
- 给一次变更写 review、deploy 和 PR handoff。

## 5. 常见误区

- 误区：Agent 越复杂越强。现实：复杂度会放大不可控性，先做最小可用流程。
- 误区：Prompt 写好就结束。现实：可靠性来自 schema、工具契约、测试和运维。
- 误区：多 Agent 自动提升效果。现实：没有清晰角色边界时，多 Agent 只会增加噪声。
- 误区：只看一次 demo。现实：要看大量真实样例和失败样例。

## 6. 推荐学习顺序

1. Python 或 TypeScript API 开发。
2. LLM API、prompt、structured output、tool calling。
3. Agent loop 和工具契约。
4. RAG、embedding、检索评估。
5. 自动化测试、eval harness、回归测试。
6. 安全、权限、日志、部署和成本优化。
7. CrewAI 或类似框架的 crew、flow、memory、tracing 和 deploy。
8. 多 Agent、复杂规划、长期记忆等高级主题。
